- 직접 만든 `초록구름산책냥`은 실제 서브워드 추론으로 산책과 83.81, `<unk>` 0개. 사전 조회/해시/랜덤 점수가 아닙니다.

공개 운영 전에는 후보 90개의 난도와 관련 단어를 더 넓게 평가해야 합니다. 소규모 로컬 실행 기준으로 선택한 모델이며, 점수를 인위적으로 재분배하지 않습니다.

## 플랫폼별 확인 범위

| 환경/항목 | 상태 |
|---|---|
| Windows → Linux/amd64 Docker | 이미지 빌드, DB, 모델 로딩, 게임 API 실제 실행 통과 |
| Python/Node/PostgreSQL 기반 이미지 | 고정 다중 아키텍처 manifest의 amd64/arm64 제공 확인, digest 고정 |
| Linux/arm64 Python 의존성 | requirements.lock 전체 바이너리를 aarch64 대상으로 다운로드, SHA-256 검증 성공 |
| Linux/arm64 설치·모델 로딩 | **미검증**. 이 PC Docker에서 `/bin/sh: exec format error`로 빌드 중단. 별도 임시 빌더도 amd64/386만 실행 가능했으며 검사 후 정리 |
| 실제 Apple Silicon / Intel Mac | **미검증**. Mac 하드웨어에서 실행하지 않음 |
| Mac용 `db.sh` | Linux `sh -n` 구문 검사 통과; 실제 Mac에서 미실행 |
| Windows 네이티브 Python | 미검증. 호스트 Python이 PATH에 없어서 모든 서버 검사는 Linux 컨테이너로 수행 |
| Windows Chrome 클릭·시각·모바일 크기 | 최신 검사 결과는 이 문서 맨 위에 기록. 실제 모바일 기기·가상 키보드·Safari는 미검증 |

arm64 바이너리 확인은 다음 명령으로 실행했습니다(아래는 Docker Python 컨테이너 안의 명령).

```sh
pip download --only-binary=:all: --platform manylinux_2_28_aarch64 --platform manylinux_2_27_aarch64 --platform manylinux2014_aarch64 --platform manylinux_2_17_aarch64 --python-version 3.12 --implementation cp --abi cp312 --abi abi3 --abi none --require-hashes -r backend/requirements.lock -d /tmp/arm64-wheels
```

Mac에서는 README 순서대로 실제 `docker compose up -d --build`를 실행하고 모델 로딩·실제 입력·재접속·중복·자정 테스트를 다시 확인해야 합니다. amd64 이미지를 강제하지 않으므로 Apple Silicon에서는 arm64용 의존성을 설치합니다. Windows의 가상환경·실행 파일·DB 데이터 디렉터리를 옮기지 않습니다.

## 다시 검사하기

```sh
docker compose exec -T app sh -c 'TEST_DATABASE_URL="$DATABASE_URL" pytest -q backend/tests'
docker compose exec -T app python scripts/smoke_ranking.py
docker compose exec -T app python scripts/prepare_dictionary.py --check
docker compose exec -T app python scripts/prepare_word_ranks.py --check
docker compose exec -T app python scripts/benchmark_model.py
```

`smoke_ranking.py`와 규칙 검사는 임시 스키마에만 사용자를 만들고 검사 후 정리합니다. 초기 `smoke_test.py before/after`는 실제 앱에 검사 기록을 남기므로 012 정리에서 삭제했습니다. 위 과거 기록의 실제 컨테이너 재시작 검사를 이번에도 반복했다는 뜻은 아닙니다. 실제 채팅 브라우저 검사 명령은 [README](../README.md)에 있습니다.
