## 각 기록에서 볼 수 있는 것

- **무엇이 달라졌나요?** 사용자가 경험하는 변경과 이유.
- **어디를 수정했나요?** 파일 링크, 함수/컴포넌트/설정 키, 구체적인 변경 내용.
- **어떤 코드인가요?** 핵심 코드 일부와, 확인 가능한 경우 변경 전후 코드.
- **어떻게 확인했나요?** 실제 검사 결과, 실행하지 않은 검사와 이유.
- **영향과 남은 일:** DB 변경·설정 변경·재시작 필요 여부, 남은 작업.

## 앞으로 기록하는 방법

1. [TEMPLATE.md](TEMPLATE.md)를 복사해 `YYYY-MM/DD-NNN-short-title.md`로 저장합니다. 날짜는 한국 시간, `NNN`은 그날의 001부터 이어지는 번호입니다.
2. 한 가지 목적의 변경은 파일 하나에 기록합니다. 화면과 서버를 함께 바꾸었으면 같은 기록에 모두 적습니다. 독립적인 변경은 파일을 나눕니다.
3. 바뀐 파일마다 함수명, 컴포넌트명, CSS 선택자 또는 설정 키를 적습니다. 줄 번호만 적으면 다음 수정 때 어긋나므로 코드 이름과 짧은 발췌를 함께 남깁니다.
4. 그 달 `README.md`의 맨 위에 항목을 추가합니다. 새 월이면 월 폴더와 목록을 만들고 이 문서에도 링크를 추가합니다.
5. 완료한 기록은 남겨 두고, 나중의 수정은 새 파일로 추가합니다. 잘못된 기록을 고칠 때는 정정 이유를 덧붙입니다. 아직 구현하지 않은 계획을 완료 기록에 넣지 않습니다.

9월 19일에 시작한 별도 변경의 다음 번호는 `2026-09/19-014-topic.md`이며, 9월 20일 새 작업은 `2026-09/20-001-topic.md`부터 시작합니다. 여러 날 이어진 작업은 시작일 파일을 유지하고 완료 날짜를 기록합니다. 파일 이름은 짧은 영문 주제로, 제목과 설명은 한국어로 작성하면 Windows와 Mac에서 찾기 쉽습니다.

**이 문서는 파일 변경을 자동 감지하는 도구가 아닙니다.** 작업을 끝낼 때 작성하는 기록이며, [AGENTS.md](../AGENTS.md)에 Codex가 이후 작업에서도 기록을 함께 추가하도록 규칙을 두었습니다. 직접 수정한 작업은 템플릿을 복사해 적으면 됩니다.

## 최초 기록의 기준

001~004는 기존 1단계 구현을 현재 소스와 [당시 검증 기록](../docs/VALIDATION.md)으로 정리한 **초기 구현 기록**입니다. 이번 작업에서 해당 기능을 다시 변경하거나 검사했다는 뜻은 아닙니다. Git 변경 이력이 아직 없어 과거 전체 줄 단위 diff는 복원하지 않았습니다.

앞으로 코드 변경 시에는 실제 변경 전후를 기록하고, Git을 사용하게 되면 커밋 번호를 함께 적을 수 있습니다. CHANGELOG는 변경 이유와 핵심 코드를 설명하고, 전체 줄 단위 이력은 Git에서 확인하는 구성을 권장합니다.

실제 `.env` 값, 비밀번호, 세션 쿠키, DB 내용·백업, 큰 모델 파일은 기록에 복사하지 않습니다. 설정은 키 이름과 비밀값 없는 예시만 적습니다. CHANGELOG 문서는 소스와 함께 Git에 보관할 수 있습니다.
