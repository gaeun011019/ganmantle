## 무엇이 달라졌나요?

변경 이유와 사용자가 볼 수 있는 결과를 1~3문장으로 적습니다.

| 변경 전 | 변경 후 |
|---|---|
| 실제로 확인한 이전 동작. 새 기능이면 ‘없음’ | 변경된 동작과 구체적인 예 |

## 어디를 수정했나요?

아래 파일 경로를 실제 Markdown 링크로 바꾸세요. 월 폴더의 기록에서 프로젝트 루트까지는 `../../`입니다.

| 파일 | 코드 위치 | 추가·변경한 내용 |
|---|---|---|
| 프로젝트 기준 파일 경로 | 함수명 / 컴포넌트명 / CSS 선택자 / 설정 키 | 바뀐 처리와 그 이유 |

## 어떤 코드인가요?

전체 파일 대신 이해에 필요한 부분만 발췌합니다. 코드 블록에는 언어를 지정하고 실제 변경이라면 전후를 나눠 적습니다. 중간을 생략했다면 ‘일부 발췌’라고 표시하세요. 문서만 바뀌었다면 바뀐 문서 내용이나 연결 구조를 적습니다.

- 변경 전: 확인한 코드만 기록. 확인할 수 없다면 그 사실을 명시.
- 변경 후: 실제 반영한 코드와 파일·함수명.
- 설명: 코드가 왜 필요한지, 어떤 동작을 만드는지.

## 어떻게 확인했나요?

| 확인 방법 | 결과 |
|---|---|
| 실제 실행한 명령 / 직접 확인한 항목 | 통과 / 실패 / 미실행 및 이유 |

이전 검사 결과를 인용할 때는 출처와 검사일을 적고, 이번에 다시 실행했다고 표현하지 않습니다. 문서만 바뀌면 경로·내용을 확인하며 관련 없는 앱 테스트나 재시작은 생략할 수 있습니다.

## 영향과 남은 일

- DB 변경: 없음 / 새 migration 파일과 이전 방법.
- 설정·실행: 변경된 설정 키, 재설치·재시작 필요 여부. 실제 비밀값은 제외.
- 미완료·주의점: 없으면 ‘없음’. 실제 확인하지 못한 환경도 적습니다.
