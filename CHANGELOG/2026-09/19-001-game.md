## 무엇이 추가되었나요?

닉네임을 정하고 오늘 게임을 시작한 뒤 단어를 입력할 수 있습니다. 서버가 시도 횟수·시간·정답을 결정하고 PostgreSQL에 저장하여 같은 브라우저에서 이어서 플레이할 수 있습니다.

| 상황 | 구현한 동작 |
|---|---|
| 이미 쓰는 닉네임 입력 | 중복을 거부. 닉네임만으로 다른 사람의 기록에 접근할 수 없음 |
| 시작 버튼을 다시 누름 | 최초 시작 시각 유지 |
| 새 단어 입력 | 실제 모델 계산이 성공하면 시도 1회 증가 |
| ‘산책 → 바다 → 산책’ 입력 | 행은 2개, 시도는 2회, 목록은 ‘산책 → 바다’. 최초 시도 번호 유지 |
| 점수가 100으로 반올림됨 | 정규화한 정답 문자열과 같을 때만 성공 |
| 새로고침·재접속 | 쿠키로 사용자 식별, DB의 기록 복구. 닫혀 있던 시간도 포함 |
| 한국 시간 자정 | 전날 진행 게임을 미완료로 마감. 새 문제는 시작 대기. 전날 제출은 거절 |

## 핵심 코드

`game.py` → `guess()`의 중복 분기 일부입니다.

```python
conn.execute("UPDATE guesses SET last_display_order = %s WHERE id = %s", (revision, previous["id"]))
conn.execute("UPDATE games SET display_revision = %s WHERE id = %s", (revision, saved["id"]))
return True
```

새 행을 추가하지 않고 표시 순서만 바꿉니다. 이 분기에서 끝나므로 아래의 시도 증가 처리를 실행하지 않습니다.

새 입력의 정답 판정과 시도 증가입니다.

```python
correct = word == normalize(puzzle["answer"])
attempt = saved["attempts"] + 1
```

점수가 아니라 정규화한 문자열을 비교합니다. 시간 계산은 `elapsed_ms()`에 모았습니다.

```python
delta = end - start
return max(0, delta.days * 86400000 + delta.seconds * 1000 + delta.microseconds // 1000)
```
